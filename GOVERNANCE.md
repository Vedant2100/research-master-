# Scientific validity and privacy

1. Treat four tracks as always active; nine named workstreams include two hackathons. Supporting Fleet-Mem is separate.
2. Truthful stage: plan, code/CI, actual model run, replication, portal submission, acceptance.
3. Freeze evaluation split, seeds, task order, worker/prompts, memory budget and evaluator source SHA. Distinguish online-memory from held-out protocols.
4. Require task competence and positive/negative controls before a large GPU matrix. Count independent cases, not deterministic greedy seed replays.
5. Compare verified state outcomes, not answer text or training loss. Zero violations under zero task completion is not safety proof.
6. Don't label SFT as GRPO, UCB as actor-critic, sleep-time memory edits as lifelong weight learning, or small procedural gains as RSI.
7. Do not store secrets, hidden test data, real patient/company data, confidential materials, OAuth tokens or personal application answers in public sources.
8. Preserve raw traces, errors and failures, separate pilot from counted comparisons and record cost and uncertainty.
9. Do not claim hackathon submission, registration or fellowship invitation without the real receipt.
10. Project code and artifacts stay in original repositories; this master is coordination and documentation.
